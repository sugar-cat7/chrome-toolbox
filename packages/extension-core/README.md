# extension-core

Shared TypeScript library for the three extensions: the llama.cpp client, message protocols, settings, prompts and the bounded building blocks that keep memory flat. It is portable: it imports neither `wxt` nor Node, and takes browser APIs, `fetch` and timers as injected adapters, so the same code runs in a service worker, a side panel and Vitest.

## Use

The package is private to this workspace (`workspace:*`); it is not published.

```ts
import { createLlamaClient, createQueue, defaultSettings } from '@chrome-toolbox/extension-core';

const queue = createQueue({ concurrency: 1, maxPending: 16 });
const client = createLlamaClient({
  baseUrl: defaultSettings.llamaBaseUrl,
  fetch: (input, init) => fetch(input, init),
  queue,
});
// { ok: true, value: { models: ['gemma4-e4b', …] } } or { ok: false, error: AppError }
const status = await client.status();
```

Extension `src/` code does not use `console` or `throw`; it hands `Result` values to the caller or to `launch` from `contracts`. Call llama.cpp only from a service worker, never from a content script.

## Development and tests

From the repository root:

```console
pnpm --filter @chrome-toolbox/extension-core test
pnpm --filter @chrome-toolbox/extension-core check
pnpm --filter @chrome-toolbox/extension-core build
```

`test` runs the table-driven Vitest tests next to each module (`src/*.test.ts`) with fake `fetch`, storage and timers; no server or browser is needed. `build` packs the library with Vite+ (`vp pack`). The Playwright fixtures in `testing/` run as part of each extension's `test:e2e`; `testing/*.test.ts` drives the llama.cpp stub with the real client and Clef judge, so a format change fails here first.
