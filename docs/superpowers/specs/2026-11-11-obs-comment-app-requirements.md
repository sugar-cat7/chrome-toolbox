# OBS コメント中継デスクトップアプリ — 要求定義書

日付: 2026-11-11
状態: 要求定義（レビュー待ち）
関連: [chrome-ai-extensions-design](2026-10-28-chrome-ai-extensions-design.md)（コメントアシスタントの設計）、[adoption](../../adoption.md)（モデル計測と採用判断）

## 1. 背景・目的

現在のコメントアシスタントは Chrome 拡張であり、フィルターと翻訳の結果は拡張のサイドパネルとチャット上の表示にしか出せない。配信者が OBS で配信するとき、視聴者に「フィルター済み・翻訳済みのコメント」をオーバーレイ表示したい、あるいはコメント欄を持たない配信スタイルでコメントをさばきたい、という用途に拡張は向かない。

この文書は、そのための中間層 — **チャット取得 → フィルター/分類 → 翻訳 → ローカル配信** を担う超軽量デスクトップアプリの要求を定義する。推論はすべてローカルの llama.cpp サーバーで行い、外部サービスへは一切送信しない。

## 2. スコープ

### やること

- YouTube ライブチャットと Twitch チャットの取得
- コメントのフィルター（荒らし判定）と強度の調整
- コメントの日本語翻訳
- フィルター・翻訳済みコメントをローカルエンドポイント経由で配信し、OBS Browser Source 等から購読できるようにする
- バックグラウンド常駐（メニューバー常駐またはサービス化）での動作
- 超軽量なデスクトップアプリとしての配布（インストーラ + llama-server バイナリ同梱、モデルはユーザーがダウンロード）

### やらないこと（今回のスコープ外）

- 字幕の音声認識（ASR）。採用モデルが翻訳・分類専用のため、ASR には別系統（whisper.cpp 等）が必要であり、本アプリの対象外とする
- ページ翻訳。印のある単位（リンク・強調・コード）を安全に訳すには Gemma が必要であり、本アプリは Clef + PLaMo の2モデル構成を前提とする
- コメント要約・ジャンル推定など、判定モデルの守備範囲を超える分析機能
- Chrome 拡張の置き換え・統合。拡張は並存する別製品として残す

## 3. 利用シナリオ

1. 配信者がデスクトップアプリを起動し、YouTube または Twitch の配信ページを指定する
2. アプリがチャットを読み取り、Clef-Flash で荒らし判定、PLaMo で日本語翻訳を行う
3. アプリが `http://127.0.0.1:<port>` でフィルター・翻訳済みコメントのストリーム（WebSocket または SSE）と、OBS Browser Source がそのまま読めるオーバーレイページを提供する
4. OBS の Browser Source にその URL を登録すると、配信画面にコメントがオーバーレイされる
5. 配信中もアプリはバックグラウンドで動き続け、メニューバー等から状態確認・フィルター強度変更ができる

## 4. 機能要件

### 4.1 チャット取得

- YouTube ライブチャット: 現行拡張と同じくページ DOM からの読み取りを基本とする。デスクトップアプリ内の WebView（Tauri）で配信ページを開き、content script 相当のロジックでコメントを取得する。InnerTube API などの非公式 API 直叩きは、仕様変更への脆弱性から採用しない
- Twitch チャット: 既存のサイトアダプタと同等の取得を行う。公式 IRC/EventSub の利用も選択肢とするが、要件としては「YouTube と同等のコメント単位・タイムスタンプ・ユーザー情報が取れること」とする
- 取得はバックグラウンドで継続し、UI を閉じても（メニューバー常駐時）処理が止まらないこと

### 4.2 フィルター・翻訳

- Clef-Flash による荒らし判定と、既存のフィルター強度（約3段階）を踏襲する
- PLaMo 3 Translate 2B による日本語翻訳。1ユーザーメッセージ形式・`chat_template_kwargs.target_lang = "ja"` など、既存の `plamoTranslateRequest` の契約をそのまま使う
- 判定・翻訳は既存パイプラインのバッチ処理・キャッシュ・フォールバック方針を踏襲し、取得ストリームを止めない（コメントの流れを優先し、処理待ちは bounded）
- 原文と翻訳文の両方を配信データに含め、表示側で選べるようにする

### 4.3 OBS 向け配信

- ローカル HTTP/WebSocket サーバーをアプリ内に持ち、フィルター・翻訳済みコメントをリアルタイム配信する
- OBS Browser Source がそのまま開けるオーバーレイ用 HTML ページを提供する（透明背景、コメントの逐次追加・自動スクロール・件数上限）
- 配信データは localhost のみに bind し、外部からアクセスできないこと

### 4.4 設定・運用

- llama.cpp サーバー URL の設定（デフォルト `http://127.0.0.1:18083`）。アプリ同梱の llama-server を使う場合は自動起動・停止も行う
- フィルター強度・表示件数・翻訳 ON/OFF・対象言語などの設定を永続化する
- モデル未ダウンロード時は、必要なモデルと公式入手先（Hugging Face のピン留めリビジョン + SHA256）を案内し、ダウンロードを補助する

## 5. 非機能要件

- **軽量**: アプリ本体（Tauri + WebView）はインストーラ数十MB 程度。常駐時のメモリ・CPU は最小限とし、アイドル時は推論リクエストがない限り llama-server への負荷をかけない
- **プライバシー**: コメント本文・翻訳結果・配信 URL を外部へ送信しない。テレメトリなし。推論はすべて localhost の llama.cpp のみ
- **リソース上限**: キュー・キャッシュ・保持件数は既存実装と同様に上限を持ち、長時間稼働でリーク・肥大化しない
- **堅牢性**: llama-server 停止・モデル未ロード・ページ遷移時もクラッシュせず、状態を表示して復帰できる

## 6. 技術前提・制約

- **フレームワーク**: Tauri（Rust + WebView）を第一候補とする。WebView で YouTube/Twitch のページを開いて DOM からチャットを読む構成は、既存 content script のロジックをほぼ移植できる
- **推論**: llama.cpp ルーター（`--parallel 3`）。Clef-Flash と PLaMo 3 Translate 2B の2モデル構成。スロット割当は既存方針を参考にする（本アプリ専用なら競合は少ない）
- **内部ロジック流用**: `packages/extension-core` は WXT 非依存・adapter 注入のポータブル設計であり、プロンプト構築・フィルター判定・`plamoTranslateRequest`・Result 型・bounded queue/cache を再利用する。`packages/contracts` のスキーマと `packages/ui` の表示部品も候補
- **llama.cpp バイナリ**: MIT ライセンスのためデスクトップアプリへの同梱は可能。Chrome 拡張と異なりストア審査の制約がない
- **モデルライセンス**: Clef-Flash は Apache-2.0。PLaMo 3 Translate 2B は PLaMo Community License（非商用無料・商用は要登録・翻訳提供時は "Built with PLaMo" 表記）。モデル重みは再配布せず、ユーザーが公式ソースからダウンロードする方式を前提とする
- **配布**: デスクトップアプリとしてインストーラ配布を想定。Chrome Web Store は経由しない

## 7. 未決事項（オープンクエスチョン）

- YouTube チャット取得を「アプリ内 WebView での DOM 読み」と「既存 Chrome 拡張からの中継」のどちらにするか。前者は拡張不要で完結するが実装量が増え、後者は拡張依存になるが既存資産をそのまま使える
- Twitch を公式 IRC/EventSub にするか、WebView DOM 読みに統一するか
- OBS オーバーレイの表現力（単純なコメント流しか、既存拡張のようなカテゴリ色分け・非表示バーまでやるか）
- llama-server をアプリに同梱して自動管理するか、ユーザーの既存サーバーに接続するだけにするか（両対応が無難か）
- 対応 OS の範囲（macOS arm64 のみか、Windows/Linux も最初から対象にするか）
- フィルター強度の段階数と、既存拡張の設定項目のどこまでを引き継ぐか

## 8. 既存資産の流用マップ

| 資産                                                                                            | 流用先                                 |
| ----------------------------------------------------------------------------------------------- | -------------------------------------- |
| `packages/extension-core` のプロンプト・フィルター・`plamoTranslateRequest`・queue/cache/Result | 判定・翻訳パイプライン（ほぼそのまま） |
| `packages/extension-core` のサイトアダプタ（YouTube/Twitch の DOM 読みロジック）                | WebView 内チャット取得                 |
| `packages/comment-assistant` のパイプライン制御（バッチ・hold・フォールバック・非表示リスト）   | 中継ロジックの設計参照                 |
| `packages/ui` の React 部品                                                                     | 設定画面・オーバーレイページ           |
| `docs/llama-server.md` のモデルピン・SHA256・起動手順                                           | モデル DL 補助と同梱サーバー設定       |
| `packages/bench` の slots/clef/translate 計測                                                   | 性能検証                               |
